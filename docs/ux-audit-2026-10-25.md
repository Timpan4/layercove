- Item 19: the binding card offers "Add Bambu Lab P1S 0.4 nozzle from the standard library"

  revisions in review, so the button runs sync, approves the pending standard batch, then
  activates only the chosen preset, and refetches so "Use suggestion" appears. Approving only

# LayerCove UX review (layercove.timpan.dev, v0.2.4.9, 2026-10-25)

Method: logged-in walkthrough in the T3 browser at 1280x800, reading each page's DOM and
opening dialogs. No print controls were touched. Pages visited: Printers dashboard, printer
detail ("Open controls"), Filament inventory + Add Spool dialog, Archives, Print Queue,
Projects, File Manager, MakerWorld, Profiles, Maintenance, Statistics, Settings (General).
Not verified: mobile layout (viewport resize did not apply in the hidden tab; one inventory
screenshot at 539px wide is the only narrow-width evidence), keyboard-shortcuts dialog
(did not open from a scripted click), SpoolBuddy pages, user/group admin.

## Bugs seen in production

1. Printer detail overflow button renders the raw key "+{{count}} more" as its tooltip.
   `frontend/src/pages/PrintersPage.tsx:3041` calls `t('common.more', 'More')` but
   `common.more` is defined as `'+{{count}} more'` in `en.ts:164`. Needs its own key.
2. Statistics says "Filament Used 0g" and "By Material: Unknown 0g" while Filament
   inventory reports 840g consumed. Two sources of truth disagree on the same page set.
3. Archives show "0 B" for every Bambu print (no 3MF pulled). A zero size is presented as a
   fact rather than "not archived".
4. Archive cards show bare "-2%", "-1%", "-0%" badges (time-accuracy deviation) with no
   label; the meaning is only in a hover tooltip. "-0%" should never render.
5. Keyboard-shortcuts button in the sidebar footer did not open anything on click
   (scripted); unverified with a real pointer.
6. Settings > Sidebar lists "Notifications: Visible in sidebar" but the sidebar has no
   Notifications entry.

## Workflow findings

### 1. Dashboard (Printers)
- First thing a user reads is "FLEET PLUS FOCUS" and "Command deck". Internal layout names
  leaked into the UI. The page should just say Printers.
- Printer card is a single big `role=button` with "Inspect" and "Live telemetry" rendered as
  text, not controls; there is no visible affordance for what clicking does.
- Filter bar (search, status, location, sort, hide offline) is shown even for a 2-printer
  fleet. Hide it below N printers or collapse into one "Filter" control.
- Right pane repeats the left card (name, status, job, progress, temps, filament) and adds
  "NEXT BEST ACTION: Monitor this print" and "MACHINE STATE: No action needed", both filler.
- Two sources of printing state on one screen (card + focus pane) update independently
  (card said 75% while pane said 72%).

### 2. Printer detail ("Open controls")
- Header text runs together: "P1S• 0.4mm629h" (model, nozzle, hours with no separators).
- Two unlabeled green "OK" chips next to the firmware version; nothing says what is OK.
- Pause and Stop are adjacent same-sized buttons with no confirmation visible. Stop should
  be visually distinct and confirmed.
- Button labels carry state as prose: "Disabled while printing", "Plate check disabled -
  Click to enable", "AMS Filament Backup is OFF. Click to enable." Use a labeled toggle.
- "Installed printer slicer bindings" with "rollout state" copy is developer language on a
  user page; this belongs under an advanced section or Settings.
- Three unlabeled percentages (47%, 0%, 67%) under temperatures (fan speeds, presumably).

### 3. Filament inventory
- Add Spool is a 21-field form in one scrolling dialog (1186px tall) with two tabs and a
  "Quick Add (Basic)" toggle off by default. Quick Add should be the default; full form
  behind "More fields".
- Five stat tiles, two view toggles (Table/Cards/Forecast), three filter chip groups,
  two selects, Columns and Group menus, and five header actions all above a 2-row table.
  Controls outnumber data. "Print labels…" is disabled with no reason shown.
- Table needs horizontal scroll at narrow widths (screenshot shows a scrollbar after
  5 columns). Cards should be the default below tablet width.
- "Reset all counters" is an icon button on the Total Consumed tile, one click from
  destroying tracking data (confirmation not verified).

### 4. Archives
- 43 cards each with 9 always-visible action buttons (Favorite, 3D Preview, Photo, Edit,
  Print, Open in Slicer, External link, Download, Delete) plus a hidden file input. Show
  Print as primary, the rest in the context menu that already exists.
- Three stacked filter rows (view/time select, printers, materials, file type, favorites,
  hide failed, hide duplicates, sort). Duplicates are common (same file printed 4 times);
  grouping repeats of the same file into one card with a print count would cut the list by
  roughly half.
- "#43" numbering, "GCODE" badge, "0 B", and printer name are shown with equal weight to
  the file name. The thumbnail banner ("Store sent files on external storage") is useful but
  should link straight to the printer's settings, not "install step 4".
- Status chips use lowercase strings ("failed", "cancelled") while the rest uses Title Case.

### 5. Print Queue
- Empty state: "Open Archives, choose Print for a file, then select Queue." A three-step
  detour. Add "Add from Archives" and "Upload file" buttons to the empty state.
- Five summary tiles (0 Printing | 0 Queued | 0m | 0g | 3 History) above an empty list; the
  "SJF" view toggle (shortest job first) is an unexplained acronym.
- Four tabs (Queue, History, Timeline, Pipelines) and three selects for an empty queue.

### 6. Projects
- Page shows "Loading..." with no skeleton, then a card with "0/1 parts", "plates 0 / 1",
  "parts 0 / 1", "0 plates", "0 parts": the same two numbers four times. A single
  progress line is enough.
- Only entry action is "New Project"; nothing explains what a project is or links to the
  archives/files it would be built from.

### 7. File Manager
- Toolbar mixes user actions (Upload, New Folder) with admin tasks (Generate Thumbnails,
  Link External, Purge old, Tags). Move admin tasks to an overflow menu.
- The same file appears three times (Voron_Design_Cube_v8_PLA_24m37s.gcode x3) with no
  hint that they are copies. Show "Printed 1x" style data consistently, and offer dedupe.
- "Free: 282.8 GB" is a host disk stat, not something most users need in the header.

### 8. MakerWorld, Profiles, Maintenance
- MakerWorld: good. Clear single input and an honest "sign-in required" note.
- Profiles: lands on a Bambu Cloud login form with six tabs (Bambu Cloud, Orca Cloud, Local
  Profiles, K-Profiles, Shared catalog, Calibration). Default to Local Profiles; put cloud
  sign-in behind a "Connect" button. "K-Profiles" is jargon for pressure-advance presets.
- Maintenance: simple and readable. Keep this as the model for other pages.

### 9. Statistics
- "Drag widgets to rearrange. Click the eye icon to hide." as the subtitle, plus Reset
  Layout, Recalculate Costs, Export Stats. The customization tooling is louder than the
  numbers.
- Time Accuracy "110% / +10%": the metric is inverted from what people expect (should read
  "prints take 10% longer than estimated").
- Energy 0.000 kWh and kr 0.00 tiles appear with no smart plug configured; hide empty
  metrics instead of showing zero.

### 10. Settings
- General tab alone is 2191px tall with 12 sections (General, Appearance, Dark Mode, Light
  Mode, Archive Settings, Camera, External Cameras, Cost Tracking, File Manager, Data
  Management, Updates, Sidebar) behind 12 top-level tabs. Nothing is searchable.
- Appearance has 6 background, 6 accent and 3 style choices, duplicated for dark and light.
  Reduce to theme + accent.
- Long help copy inline under toggles (the finish-photo paragraph is 60+ words).
- Currency select lists 31 currencies with symbol variants; use a searchable select.

## Cross-cutting

- Information density: every list page stacks header actions, stat tiles, view toggles,
  and multi-row filters above the content. On a 1280x800 window the first archive card
  starts around 400px down.
- Vocabulary drift: Filament vs Spool Inventory; Archives vs Print Log vs History; Inspect
  vs Open controls; K-Profiles vs Calibration; Command deck. Pick one name per concept.
- Developer leakage: layout names, "rollout state", "slicer bindings", "SJF", raw i18n key.
- Zero-as-data: "0 B", "0g", "0.000 kWh", "-0%". Show "not tracked" or hide the tile.
- Page components are very large (PrintersPage 9360 lines, SettingsPage 6472, ArchivesPage
  4351). Any rewrite should split these by workflow before changing visuals.

## Suggested rewrite direction (keeping all features)

1. Dashboard: one card per printer, status-first, with a single primary action per state
   (Printing: Open; Finished: Clear bed/Print next; Idle: Print). Move the focus pane into
   the detail page. Drop the layout labels.
2. Detail page: job, temps, filament, camera, then Controls in a distinct danger-styled
   group with confirmation on Stop. Advanced sections (bindings, calibration, plugs)
   collapsed by default.
3. One "Start a print" flow reachable from Dashboard, Queue, Archives and Files: pick file,
   pick printer (default printer pre-selected), pick AMS mapping, Print or Queue. Today it
   lives only inside Archives.
4. List pages (Archives, Files, Inventory): one toolbar row (search, Filter menu, Sort,
   View), stat tiles collapsed into a single summary line, card actions reduced to one
   primary button plus a kebab menu.
5. Quick Add as the default spool form; full form on demand.
6. Settings: grouped sidebar with search, each setting one line of help text, advanced
   options collapsed, appearance reduced to theme + accent.
7. Replace zeros with explicit "not tracked" states and unify the stats source with the
   inventory consumption data.

# Addendum: slicing workflow (2026-10-25)

Walked: Files > STL card menu > Quick slice (modal) with both printers selected; Files >
Edit in workbench (`/slicer/workbench?library_file=16`) with Tim Voron selected and the
filament list expanded; Archives > Open in Slicer (desktop handoff, source read only);
Settings > Workflow "Use Slicer API"; the binding form source. Nothing was sliced or printed.
The prior audit in `docs/slicing-ux-audit-2026-09-22.md` lists 19 findings; commits #148-#154
and #273-#308 since then fixed bed geometry, binding recovery link, search, undo/redo,
multi-plate scope, output retention, estimates and reopen. The items below are what is
still in the way today.

## What makes slicing annoying

1. The main printer cannot be sliced for at all. Choosing DOGGE'S PRINTER (P1S) shows an
   empty "Choose exact binding" select and "has no active slicer binding. Add one before
   slicing." The link goes to a dashboard card titled "Installed printer slicer bindings"
   whose form asks for Printer profile, Expected nozzle, Tool index and Rollout
   (Shadow/Enforced). A user with one Bambu printer has to learn what a binding is before
   their first slice. The backend already has a P1S suggestion endpoint; nothing on the
   dashboard offered it.
2. Three slicing actions plus a global mode switch. The file menu offers Quick slice,
   Edit in workbench and Run with pipeline. Settings > Workflow "Use Slicer API" changes
   what "Slice" means everywhere (in-app vs desktop URI handoff) and describes itself as
   "call the slicer-API sidecar". Archives has a fourth path, "Open in Slicer", that launches
   Bambu Studio or Orca on the desktop.
3. Wrong filament by default, then a checkbox to confirm it. For a plain STL on Tim Voron
   the dialog auto-selects "Inslogic 95A TPU @System", reports "Filament material is
   unverified", and requires ticking "Confirm filament materials before slicing. Filament 1:
   source material unknown, selected profile material unknown". The user confirms something
   the UI says it does not know. Slice stays disabled until then.
4. Finding PLA means reading 28 rows of provenance jargon. Filament groups are "Selected
   printer (1)", "Other installed printers (0)", "Unclassified (28)", "Incompatible (0)".
   Each row reads like "Bambu PLA Matte @voron · orca_cloud Manual confirmation required ·
   compatibility unknown, nozzle match". No grouping by material, no link to the spools
   loaded in the AMS (the dashboard knows ASA, ABS and PETG are loaded), empty groups still
   rendered. The process list has the same shape.
5. Printer-irrelevant controls. A "Build plate" select with Bambu plate names (Cool Plate,
   Textured PEI...) is shown before any printer is chosen and stays for the Klipper Voron.
   "Arrange on selected printer bed" carries two separate hint sentences.
6. Workbench opens in a warning state before the user has done anything: "Select a printer
   and an exact profile to view the bed", "Bed geometry unavailable. Preview only; printer
   fit and placement are unverified", footer "Object count unavailable", "Editor loaded",
   and the Orca git hash twice ("OrcaSlicer 2.4.2 · 1e646235e4"). Settings sidebar is
   1388px tall with the same printer/filament selector as the modal stacked above
   Simple/Advanced/Expert x Global/Quality/Strength/Speed/Support/Multimaterial/Others.
   Seam position shows raw enum values ("aligned_back").
7. Printer option labels are implementation strings: "Tim Voron · Voron 2.4 300 0.4
   nozzle - my · 0.4 mm · tool 0". Settings has a "Default Printer" preference; the slice
   dialog still opens on "Choose physical printer" (default was unset in this account, so
   pre-selection is unverified).
8. Readiness copy is a status report, not an instruction: "Confirmation required before
   slicing." / "Nozzle confirmed 0.4 mm" / "administrator mapping, nozzle match". The one
   thing the user needs ("pick a PLA profile, or confirm TPU") is never stated.

## Rewrite direction for slicing

1. One Slice button. Quick slice is the workbench in Simple mode with the settings drawer
   collapsed; "Run with pipeline" becomes "Use saved preset" inside it. "Open in Bambu
   Studio / OrcaSlicer" is its own action, always available, independent of the Use Slicer
   API switch. Remove the switch from the meaning of "Slice".
2. Printers are sliceable out of the box. Create the binding automatically for Bambu
   printers from model plus reported nozzle (suggestion endpoint exists), and show a
   one-question setup for Klipper printers: "Which Orca printer profile matches Tim Voron?"
   with nozzle prefilled from telemetry. Tool index and rollout state go under Advanced.
3. Filament picker: group by material, lead with spools currently loaded in the printer,
   show name + material + a source icon, keep compatibility reasons in a tooltip, hide empty
   groups. Never pre-select a profile whose material does not match the source; if the
   source has no material, leave the slot empty and say "Choose the filament you will print
   with" instead of pre-selecting TPU plus a checkbox.
4. Show only controls that apply to the chosen printer (plate type for Bambu only, AMS slot
   mapping for Bambu, nothing for Klipper beyond process/filament).
5. Readiness as one sentence with a fix-it button: "Ready to slice for Tim Voron with Voron
   Generic PLA" or "Pick a filament profile for slot 1". Drop the git hash, "Editor loaded",
   "Object count unavailable" and raw enum values from the workbench.
6. Remember the last printer, process and filament per printer (preference save already
   exists per binding) and honor the Default Printer setting.
